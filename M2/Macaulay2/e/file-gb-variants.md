# `gb-homog2`, `gb-sugarless`, `gb-toric`, `gb-walk` — GB algorithm variants

Beyond the default `gbA` ([`file-gb-default.md`](file-gb-default.md)), the
engine ships four additional Gröbner basis strategies, each tuned for a
specific input shape. This page covers the four together.

All four are subclasses of [`GBComputation`](file-comp-gb.md). Part of the
[Gröbner bases](groebner-bases.md) area.

[← per-area: groebner-bases](groebner-bases.md) · [← engine overview](README.md)

## `gb-homog2` — homogeneous specialisation

`gb_homog2_comp` is a specialised algorithm for **homogeneous** ideals. It
exploits the fact that S-polynomial degrees are monotonically increasing and
processes by degree:

```text
for d = mindeg, mindeg+1, …:
    add all input polynomials of degree d
    process all S-pairs of degree d to completion
    yield basis-up-to-degree-d (resumable)
```

This degree-by-degree loop is what makes homogeneous GB resumable with
`DegreeLimit =>` cleanly. Over a general (non-homogeneous) input, `gbA` does
the same job but with extra sugar bookkeeping.

## `gb-sugarless` — Buchberger without sugar

`gb-sugarless` is `gbA` minus the **sugar heuristic**: S-pairs are chosen
purely by leading-monomial degree rather than by sugar (the degree the
S-polynomial would have *if* nothing reduced away).

This is useful for:

- **Regression testing** — sugar can mask algorithmic bugs.
- **Pathological inputs** where the sugar heuristic guesses wrong.

It is rarely faster than `gbA` on real input.

## `gb-toric` — toric ideal GB

`binomialGB_comp` is a GB algorithm specialised to **toric ideals** — ideals
generated by binomials `m_1 - m_2` where each `m_i` is a monomial. The
relevant data structure (declared at the top of `gb-toric.hpp`):

```cpp
struct binomial {
    monomial0 lead;
    monomial0 tail;
};
```

Each "polynomial" is just a pair of monomials; arithmetic skips coefficient
handling entirely. On large toric inputs (e.g. lattice ideals) this can be
orders of magnitude faster than the general path.

## `gb-walk` — the Gröbner walk

`gb-walk.cpp` implements the **Gröbner walk** algorithm: given a GB with
respect to one monomial order, walk to a GB with respect to a different
order without recomputing from scratch. The two orders are connected by a
path through the space of weight vectors; at each step the algorithm
computes a single S-polynomial / update.

The header notes: "Not yet working?" — i.e. this implementation is
experimental. It is invoked only with explicit `Strategy => GroebnerWalk` and
should be considered an alpha-quality option.

## How to invoke

```m2
gb(I, Strategy => Homogeneous)        -- selects gb-homog2
gb(I, Strategy => Sugarless)          -- selects gb-sugarless
gb(I, Strategy => Toric)              -- selects gb-toric
gb(I, Strategy => GroebnerWalk)       -- selects gb-walk
```

When no `Strategy =>` option is given, the dispatcher in
[`file-comp-gb.md`](file-comp-gb.md) picks a default — usually `gbA` or F4
depending on the ring.
