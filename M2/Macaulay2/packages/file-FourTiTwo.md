# `FourTiTwo.m2` — interface to the 4ti2 toric algorithms library

The `FourTiTwo` package is M2's **interface to the external 4ti2
library** — a collection of algorithms for toric ideals, Markov
bases, Graver bases, circuits, and Hilbert bases. Like
[`Bertini`](file-Bertini.md) and [`PHCpack`](file-PHCpack.md), it's
an external-library-wrapper package: it writes 4ti2 input files,
shells out to the `4ti2` binary, and parses the output back into
M2 types.

The package is **widely depended on**: [`Polyhedra`](file-Polyhedra.md)
re-exports it (for the `Hilbert basis of a cone` via 4ti2's
`hilbertBasis`); [`BernsteinSato`](file-BernsteinSato.md) imports
it; [`HolonomicSystems`](file-HolonomicSystems.md) imports it (for
`gkz` system construction).

- File: `FourTiTwo.m2` (860 lines — single file)
- Authors: Mike Stillman, Josephine Yu, Sonja Petrovic
- Version: 1.0 (February 2009 — long-stable)
- Re-exports: [`Polyhedra`](file-Polyhedra.md)
- Configuration: `"path" => ""` (the 4ti2 binary path), `"keep files" => true`
- **Requires 4ti2 installed externally** (the upstream library is one binary plus several `<exe>-<algorithm>` subcommands like `4ti2-markov`, `4ti2-groebner`, etc.)

## Exported API

### Toric-ideal algorithms

```m2
toricMarkov A                       -- a Markov basis for the toric ideal of A
toricMarkov(A, S)                   -- same, returning an ideal in ring S
toricGroebner A                     -- Gröbner basis of the toric ideal
toricGroebner(A, S)                 -- same, returning an ideal in S
toricCircuits A                     -- the circuits of A
toricGraver A                       -- a Graver basis (universal GB)
toricGraver(A, S)                   -- same, returning an ideal
toricGraverDegrees A                -- degree sequence of the Graver basis
```

### Hilbert basis (re-exported from `Polyhedra`)

```m2
hilbertBasis(A, InputType => …)     -- Hilbert basis of the cone {x : Ax >= 0}
```

`hilbertBasis` is **defined in `Polyhedra`** but **this package
overrides its `Matrix`-input method** to call 4ti2's
`hilbertBasis` subcommand, which is dramatically faster than the
pure-M2 fallback for large cones.

### File I/O helpers

```m2
putMatrix(F, B)                     -- write a matrix B to file F in 4ti2 format
getMatrix filename                  -- read a 4ti2-format file into a Matrix
toBinomial(M, S)                    -- turn a matrix into a binomial ideal in S
                                    -- (used internally + exposed for direct use)
```

### Options

```m2
InputType => "lattice"|"matrix"|null  -- whether the input matrix encodes a lattice or a homomorphism
Precision => 32|64|... (in bits)      -- working precision for the underlying GMP arithmetic
Weights => list                       -- optional weight vector for toricGroebner
```

## What 4ti2 does

4ti2 is an **integer-programming-style toolkit** for problems related to lattice ideals and toric algebras. Its centerpiece operation: given an integer matrix `A ∈ ℤ^{d×n}`, compute the **toric ideal `I_A`** — the kernel of the ring map `k[x_1, …, x_n] → k[t_1^{±1}, …, t_d^{±1}]` sending `x_i ↦ t^{a_i}`.

`I_A` is generated by binomials `x^u - x^v` where `u, v ∈ ℕ^n` satisfy `Au = Av`. The package's various functions enumerate **different generating sets** of `I_A`:

| Generating set | Function | Properties |
|---|---|---|
| Markov basis | `toricMarkov A` | Smallest generating set in some technical senses; foundational in algebraic statistics |
| Gröbner basis (w.r.t. an order) | `toricGroebner A` | Specific to a monomial order |
| Circuits | `toricCircuits A` | The minimal "fundamental cycles" of the lattice |
| Graver basis | `toricGraver A` | The universal GB — contains every reduced GB |
| Hilbert basis (of the cone, not the ideal) | `hilbertBasis A` | The unique minimal generating set of the cone of non-negative integer solutions |

These are **classical objects in integer programming and algebraic statistics**, and 4ti2 is the standard tool for computing them.

## How the interface works

```
M2:  toricMarkov A
   ↓
write matrix A to a temp file in 4ti2 format (via putMatrix)
   ↓
shell out to `4ti2-markov` (or `markov` depending on version)
   ↓
parse the output file (via getMatrix)
   ↓
return as M2 Matrix (or as an Ideal in S, if S provided)
```

The package's `Configuration => { "path" => "" }` lets users override the binary path. The `"keep files" => true` configuration retains the 4ti2 temp files after the run — useful for debugging or for inspecting the exact input/output 4ti2 saw.

## Modern alternative for some operations

The newer engine path (`rawColon`, `monideal`-side toric tooling) handles some 4ti2 operations natively, faster:

| Operation | Faster alternative |
|---|---|
| `hilbertBasis` on a small cone | Pure-M2 fallback in `Polyhedra`'s default path |
| `toricGroebner` on a small ideal | M2's general `gb` engine |
| Operations only needing `In(I_A)` | Direct GB computation in M2 |

But for **large-scale or specialised operations** (Markov basis, Graver basis, circuits), 4ti2 remains the industry standard — and the package's main reason to exist.

## When this is slow

| Symptom | Try |
|---|---|
| `toricMarkov A` slow for large `A` | The Markov-basis computation is inherently hard; consider whether you actually need the full Markov basis or just any toric-ideal generating set (`toricGroebner` for one order) |
| `toricGraver A` very slow | Graver bases grow exponentially; bounded `Precision` doesn't help — the algorithm is fixed-precision |
| `hilbertBasis` for a high-dim cone | This is where 4ti2 dramatically wins over the pure-M2 fallback; ensure the binary is installed and on `PATH` |
| 4ti2 not found | Set `Configuration => { "path" => "/abs/path/to/4ti2/bin/" }` or check `programPaths#"4ti2"` |
| Out of memory on a moderate input | The bottleneck is the size of intermediate state during the algorithm; 4ti2 sometimes streams to disk; check `"keep files" => true` and inspect the temp directory |

## Common 4ti2 versions

| Version | M2-side notes |
|---|---|
| 1.6.x | Older binaries; some subcommands have different names |
| 1.7+ | Standard modern interface |

The package detects version dynamically and adapts where needed. Set `debugLimit = 10` (the global) to see exactly what shell-out commands are being run.
