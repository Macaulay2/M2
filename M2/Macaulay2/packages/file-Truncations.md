# `Truncations.m2` — truncation of modules, ideals, & matrices

The `Truncations` package implements **truncations** of modules,
ideals, matrices, and rings — restricting to elements of degree at
or above a specified bound. **Not auto-loaded**, but **re-exported
by [`Complexes`](file-Complexes.md)** (which is auto-loaded), so it
is effectively always available.

`truncate` is the main verb. Variants exist for single-grading
(`ZZ`), multi-grading (`List` of degrees), and matrices (preserve
the induced map on truncations). The package also exports `effCone`
/ `nefCone` (and their `*Generators` matrix counterparts), which
characterise which degree-vector targets actually have non-empty
truncations.

## Exported API

```m2
truncate(d, M)            -- M_{>=d} (single-grading)
truncate(degs, M)         -- multi-grading: degs is a list of vectors
truncate(d, I)            -- ideal version
truncate(d, R)            -- ring (returns an ideal in R)
truncate(d, f)            -- matrix version (induced map on truncations)

effCone R                 -- effective cone of degrees
effGenerators R           -- generators of effCone as a matrix
nefCone R                 -- nef cone (often the dual)
nefGenerators R           -- generators of nefCone
```

Note: `truncate` itself is exported by Core (the symbol must exist
before this package loads, because other Core code references it).
This package provides the actual method definitions.

### Options

```
Cone => null              -- pre-computed cone for the target degree
MinimalGenerators => true -- trim the output (drop redundant generators)
Exterior => {}            -- variables to treat as exterior-algebra
                          -- generators (degree-1, square-zero)
```

## What "truncation" means

Given a graded module `M` over a graded ring `R`, the **truncation
at degree `d`** is the submodule:

```
M_{>=d}  =  ⊕_{e >= d}  M_e
```

— all elements of `M` of degree at least `d`. Generators of
`M_{>=d}` are the elements of `M` whose degrees are at the
boundary `>= d`.

For an ideal `I`, `truncate(d, I) = I ∩ R_{>=d}`. For a ring `R`,
`truncate(d, R) = R_{>=d}` viewed as an ideal of `R`. For a matrix
`f : F → G`, `truncate(d, f)` is the induced map between the
truncations of `F` and `G`.

In a **multi-graded** setting (degree-length > 1), the "≥" is
componentwise on degree vectors. The user can pass a list of
degree vectors — the truncation is then the submodule generated by
elements with degree in the intersection of `{>= d_i}` for each
`d_i` in the list.

## How it works

The package dispatches based on grading complexity:

| Case | Branch | Method |
|---|---|---|
| Standard grading, degrees `{0}` only | `truncation1(min degs, M)` | Fast path: just take basis elements of high enough degree |
| General grading | `truncation0(deg, M)` | General path: compute the truncation polyhedron, then enumerate monomials |
| Module is free | direct path via `truncationMonomials` | Avoid trimming overhead |
| Module is `subquotient` | recurse into `image generators` and `image relations` then re-assemble | Preserves the subquotient structure |
| Module is zero | trivial return | (early-exit at the top) |

The `truncationPolyhedron` helper builds a polyhedron in the
degree group representing "which monomials have degree ≥ d in the
specified target." This polyhedron's lattice points give the
generators of the truncation — that's why `Polyhedra` is required.

`truncateImplemented R` is the precondition checker: this package
supports polynomial rings, quotients, exterior algebras (via the
`Exterior` option), and a few other cases; it errors out clearly
on unsupported rings (e.g. local rings, towers).

## The `effCone` / `nefCone` exports

For a multi-graded ring `R`:

- **`effCone R`** — the **effective cone** of `R`: the cone in the
  degree group generated by the degrees of variables. A degree
  vector `d` admits a non-zero monomial iff `d ∈ effCone(R)`.
- **`nefCone R`** — the **nef cone**: dual to the effective cone in
  the standard sense from toric geometry. Overridden by the
  `Varieties` package to give the actual nef cone of a toric
  variety.
- **`effGenerators` / `nefGenerators`** — matrices whose columns
  generate the corresponding cone.

These exist because, in multi-grading, asking for "the truncation
at degree `d`" only makes sense when `d` is in the effective cone
— otherwise no generators exist and the answer is just `0`. The
package uses them internally to pre-filter the truncation
polyhedron.

## Why this matters: `Complexes` and `Varieties`

Two heavy consumers:

| Consumer | What it does |
|---|---|
| [`Complexes`](file-Complexes.md) | Truncates a free resolution at a degree bound when the user passes `LengthLimit` / `DegreeLimit`. Re-exports `Truncations` so users of `freeResolution` get `truncate` for free. |
| [`Varieties`](file-Varieties.md) | Sheaf cohomology `HH^i F` is computed via truncation: `HH^i F = (truncated F)` then `Ext`. The `GlobalSectionLimit` option directly controls the truncation bound. Varieties also overrides `nefCone` to give the proper toric nef cone. |

Outside the auto-loaded ecosystem, `Truncations` is used by many
toric-geometry packages (`NormalToricVarieties`, `LinearTruncations`,
…) that work with multi-graded rings.

## The hook architecture

`effCone`, `nefCone`, `effGenerators`, `nefGenerators` use the
`tryHooks` pattern — the default returns the polynomial-ring cone,
but `Varieties` (and other packages) inject more specific
implementations:

```m2
effCone Ring := R -> tryHooks((effCone, Ring), R,
    R -> convexHull(matrix{0_(degreeGroup R)}, effGenerators R))
nefCone Ring := R -> null   -- placeholder; Varieties overrides
```

This mirrors the strategy-hook pattern from
[`Saturation`](file-Saturation.md) but is simpler — just one
override per method, not a strategy table.

## When this is slow

| Symptom | Cause / Try |
|---|---|
| `truncate(d, M)` slow on multi-graded ring | The truncation polyhedron has many lattice points; pre-compute and cache via `Cone => fixedCone` |
| Slow on standard graded ring | Most likely the `MinimalGenerators => true` trim step; pass `false` if you don't need a minimal generating set |
| Errors "cannot use truncate with this ring type" | The ring is one of the unsupported cases (e.g. localised); use the ambient polynomial ring instead and lift |
| `effCone` slow | Cached on first call per ring; the recomputation hit is one-time |
