# `Polyhedra.m2` — convex polyhedra, cones, fans, polyhedral complexes

The `Polyhedra` package implements **convex polyhedral geometry**:
polyhedra, polyhedral cones, fans, polyhedral complexes, and all
the operations on them. **Not auto-loaded**, but **required by
[`Truncations`](file-Truncations.md)** (which is re-exported by
`Complexes`) — so any session using `freeResolution` or
`truncate` already has it loaded. This is the **most-imported
non-auto-loaded package** in the distribution.

- Main file: `Polyhedra.m2` (63 lines — just `newPackage` + a `load`)
- Auxiliary directory: `Polyhedra/` (60+ files, ~44 000 lines —
  the **largest single package** in the distribution)
- Original author: René Birkner · Maintainer: Lars Kastner
- Version: 1.10 (November 2018)
- Certification: published in [JSAG vol. 1, 2009](https://msp.org/jsag/2009/1-1/p03.xhtml)
- Imports: [`LLLBases`](file-LLLBases.md) (for lattice
  computations on lattice polytopes)

## Top-level types

```
PolyhedralObject       -- abstract base
  Cone                 -- convex polyhedral cone
  Polyhedron           -- general convex polyhedron (cone + lineality + vertices)
  Fan                  -- collection of cones meeting along faces
  PolyhedralComplex    -- collection of polyhedra meeting along faces
```

## Construction (most-used)

```m2
convexHull V                  -- the convex hull of column vectors of V
convexHull(V, R)              -- vertices V plus rays R
coneFromVData R               -- the cone generated by columns of R
coneFromHData M               -- the cone {x : Mx >= 0}
polyhedronFromHData(M, v)     -- {x : Mx >= v}
polyhedronFromInequalities    -- alias
fan {C1, C2, …}               -- the fan with those cones
fanFromGfan f                 -- import from gfan output format
polyhedralComplex {P1, P2, …} -- the complex
```

## Inspection

```m2
ambDim P                  -- ambient dimension
dim P, dim C              -- intrinsic dimension
vertices P                -- vertices (as columns)
rays C, rays P            -- rays
linealitySpace            -- the lineality space
halfspaces P              -- half-space description (H-rep)
hyperplanes P             -- equality constraints
facets P                  -- list of facets
faces(d, P)               -- faces of given codimension
maxCones F                -- max cones of a fan
maxPolyhedra Z            -- max polyhedra of a polyhedral complex
hilbertBasis C            -- Hilbert basis of a cone
latticePoints P           -- lattice points
```

## Predicates

```m2
isCompact P               -- is it a polytope?
isComplete F              -- does the fan cover all of R^n?
isFace(F, P)              -- is F a face of P?
isFullDimensional P
isLatticePolytope P
isPointed C               -- no lineality?
isPolytopal F             -- does the fan come from a polytope?
isPure F                  -- all max cones same dimension?
isReflexive P             -- reflexive polytope (a Calabi-Yau condition)?
isSimplicial F
contains(P, x)            -- point-in-polyhedron test
commonFace(P1, P2)        -- their common face
```

## Constructions (extended)

```m2
P1 ∩ P2,  P1 + P2         -- intersection, Minkowski sum
P1 * P2                   -- direct product
linearTransform(P, A)     -- image of P under linear map A
…                         -- 20+ files in extended/ implement these
```

The `extended/` subdirectory contains 20 files implementing
operations that aren't strictly polyhedral primitives but are
heavily used: Minkowski sums (`minkowskiSum.m2`), affine images
(`affineImages.m2`), direct products (`directProduct.m2`), common
face computations (`commonFace.m2`), …

`Polyhedra/loadFile.m2` is the **single source of truth** for which
files load in which order. The orchestration is deliberate: types
must be declared before methods; helpers must come before code that
uses them; deprecated wrappers come last.

## V-representation vs H-representation

The package handles both standard polytope representations:

| Representation | Data | Constructor |
|---|---|---|
| **V-rep** | Vertices + rays + lineality | `convexHull`, `coneFromVData` |
| **H-rep** | Half-spaces + hyperplanes (Mx ≥ v, Mx = w) | `polyhedronFromHData`, `coneFromHData` |

Conversion between V- and H-rep is the **Fourier-Motzkin
elimination problem**. The package has multiple implementations
(`interfaces/fourierMotzkinAlternatives.m2`), with the default
being the pure-M2 implementation; external backends can be selected
via `Strategy =>`:

- `4ti2` (when `FourTiTwo` is loaded)
- `Normaliz` (when `Normaliz` is loaded)
- `lrslib` (default; fastest for most inputs but has license
  restrictions)
- `gfan` (via the `gfanInterface` package)

Both representations are cached on every `Polyhedron` instance —
the first call to `halfspaces P` on a V-rep polyhedron triggers
Fourier-Motzkin and caches the result.

## Why this is the largest package

Polyhedral geometry has **many distinct operations** that are
non-trivial to implement (FM elimination, lattice-point counting,
Hilbert-basis computation, fan refinement, …), and each needs to
work on all four top-level types. The combinatorial explosion of
methods is why the package is so large.

The 4 820-line `documentation/` directory is itself the size of a
typical package — `Polyhedra` has unusually thorough M2-doc DSL
coverage.

## When this is slow

| Symptom | Try |
|---|---|
| V-to-H conversion (or vice versa) slow | Switch strategy: `Strategy => "lrslib"` (default, fast), `Strategy => "4ti2"` (good on lattice polytopes), `Strategy => "Normaliz"` (good on cones), `Strategy => "fourierMotzkin"` (pure M2, slow but always available) |
| `hilbertBasis C` slow | Try `Strategy => "Normaliz"` — its Hilbert-basis implementation is generally fastest |
| `isReflexive P` slow | This computes both V- and H-rep + duality; cache results between calls |
| Many small polyhedral operations | Polyhedral operations are cache-friendly; reuse `Polyhedron` objects rather than rebuilding from raw data |

## External-library dependencies

`Polyhedra` works out of the box without external libraries (pure
M2 fallback in `fourierMotzkinAlternatives.m2`), but performance
improves dramatically when **at least one** of the following is
available:

| Library | Configured by | Used for |
|---|---|---|
| `lrslib` | `M2/cmake/FindLrslib.cmake` (only relevant via system install) | Default Fourier-Motzkin |
| `4ti2` | `M2/cmake/Find4ti2.cmake` | Lattice point operations, Hilbert basis |
| `normaliz` | `M2/cmake/FindNormaliz.cmake` | Hilbert basis, Stanley decompositions |
| `gfan` | `M2/cmake/FindGfan.cmake` | Tropical / Gröbner-fan inputs |

The `interfaces/` directory exposes one `.m2` file per library
(plus the pure-M2 fallback). Each `Cone` / `Polyhedron` method
checks the active strategy and routes accordingly.
