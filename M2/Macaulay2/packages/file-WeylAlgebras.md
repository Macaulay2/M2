# `WeylAlgebras.m2` — D-module infrastructure

The `WeylAlgebras` package is the **foundational D-module
infrastructure** for M2. It defines the Weyl algebra
`W = k[x_1, …, x_n, ∂_1, …, ∂_n]` (with `∂_i x_j - x_j ∂_i = δ_{ij}`)
as an engine-supported ring type, provides the basic algorithms over
it (Gröbner bases with weight vectors, Fourier transform, dimension
and holonomicity tests, factoring), and exposes the helper machinery
that downstream D-module packages — most prominently
[`BernsteinSato`](file-BernsteinSato.md) — depend on.

The Weyl-algebra type itself lives in the **engine**
([`e/file-weylalg.md`](../e/file-weylalg.md)); this package is the
M2-level glue plus the foundational algorithms (`Dbasic`, `Gbw`,
`switch`, `newRings`, `stafford`, `makeCyclic`, `factorWA`).

- Main file: `WeylAlgebras.m2` (144 lines — load orchestration)
- Auxiliary directory: `WeylAlgebras/` (18 files, 2 205 lines code +
  `DOC/`, `EXA/`, `TST/`, `CHALLENGES/` subdirectories)
- Authors: Anton Leykin, Harrison Tsai
- Version: 1.4.1.1 (February 2023)
- Re-exports: [`Complexes`](file-Complexes.md)
- Imports: [`PrimaryDecomposition`](file-PrimaryDecomposition.md), [`ReesAlgebra`](file-ReesAlgebra.md), [`Elimination`](file-Elimination.md), `FourTiTwo`

## Exported API

### Weyl algebra construction

```m2
makeWeylAlgebra R                -- the Weyl algebra W_R for a polynomial ring R
makeWA R                          -- alias
SetVariables => false             -- option: rename the differential operators
                                    (default: ∂-prefixed copies of R's vars)
```

### Basic D-module data

```m2
Ddim M, Ddim I                    -- the Bernstein dimension (dim of the holonomic filtration)
holonomicRank M                   -- the holonomic rank
isHolonomic M                     -- is M holonomic?
dpairInds W, dpairVars W          -- indices/variables of conjugate (x, ∂) pairs
```

### Fourier transform & Weyl-algebra automorphisms

```m2
Fourier(M)                        -- D-module Fourier transform
FourierInverse(M)                 -- inverse transform
Dtransposition(M)                 -- transposition automorphism: x ↔ ∂
```

These are the standard algebraic automorphisms of the Weyl algebra (and corresponding functors on D-modules) used throughout D-module theory.

### Gröbner bases with weight vectors

```m2
gbw(I, w)                         -- Gröbner basis under a weight order
inw(I, w)                         -- initial ideal under a weight order
Dprune f                          -- prune redundancies from a presentation
```

The weight-vector machinery in `Gbw.m2` is essential because most D-module algorithms run their inner loop on Gröbner bases under specific weight orders (e.g. `(0, 1)` to compute the initial ideal at `s` for b-function calculations).

### Auxiliary rings

```m2
createIntRing W                   -- the "integration ring" used in restriction
IntRing                            -- the type tag
WtoIR(f), IRtoW(g)                 -- conversion between W and IntRing
createThetaRing W                 -- the θ-ring (theta = x∂)
ThetaRing
createHomWeylAlgebra W            -- the homogenised Weyl algebra
HomWeylAlgebra
WAtoHWA(f), HWAtoWA(g)            -- conversion
```

These auxiliary rings are constructed on demand and cached on the Weyl algebra; user code rarely calls them directly, but D-module algorithms route through them.

### Holonomic ring presentations

```m2
makeCyclic M                       -- present M as a cyclic quotient W / I
```

This is the **Stafford-Smith algorithm**: any finitely-generated module over the Weyl algebra (in char 0) is cyclic — i.e. generated by a single element. The package implements this in `WeylAlgebras/makeCyclic.m2` (223 lines). Useful when downstream algorithms assume cyclic input.

### Stafford / Smith ideal factoring

```m2
factorWA f                         -- factor an element of the Weyl algebra
                                    (when factorisation exists)
```

In `WeylAlgebras/stafford.m2` (647 lines). Generalises classical commutative-polynomial factoring to the non-commutative Weyl-algebra setting.

```

   │
   ├─→ Dbasic.m2                          — basic Weyl-algebra construction,
                                            dpair helpers, Ddim, isHolonomic,
                                            Fourier, Dtransposition
   ├─→ Gbw.m2                              — Gröbner bases under weight orders
   ├─→ switch.m2 (33)                      — basis switches between auxiliary rings
   ├─→ newRings.m2 (134)                   — IntRing, ThetaRing, HomWeylAlgebra constructors
   ├─→ stafford.m2 (647)                   — Stafford-Smith algorithms (factoring, cyclicity)
   ├─→ makeCyclic.m2 (223)                 — make-cyclic algorithm
   ├─→ factorWA.m2                          — Weyl-algebra element factoring
   │
   ├─→ TST/Dbasic.m2, Gbw.m2                ← test suite
   │
   ├─→ DOC/main.m2, basics.m2, general.m2   ← M2-level documentation
   │
   ├─→ EXA/Dbasic.exa.m2, factorWA.exa.m2,
   │      makeCyclic.exa.m2, shibuta.exa.m2,

   │
   └─→ CHALLENGES/dimca-sticlaru-2016.exa.m2  ← benchmark / challenge inputs
```

The `EXA/` directory is unusual: it's a **library of worked examples** that users can `load` into a session to follow along with the package's pedagogical material. Not loaded by default; opt-in via `load "WeylAlgebras/EXA/Dbasic.exa.m2"`.

`CHALLENGES/dimca-sticlaru-2016.exa.m2` is a notorious hard input from Dimca-Sticlaru's 2016 paper — useful as a benchmark when comparing D-module algorithm implementations.

## The Weyl algebra type — engine side

When you call `makeWeylAlgebra R`:

1. The package validates `R` is a polynomial ring.
2. Constructs a `WeylAlgebra` engine object — see [`e/file-weylalg.md`](../e/file-weylalg.md).
3. The engine knows the `(x, ∂)` pairing as a flag-based extension of `PolynomialRing`.
4. All arithmetic operations on Weyl-algebra elements route through the engine's templated arithmetic.

The engine's `WeylAlgebra` is one of three **specialised polynomial-ring variants** (alongside `SkewPolynomialRing` and `SolvableAlgebra`) — see [`e/polynomial-rings.md`](../e/polynomial-rings.md) for the mapping table.

## Weight orders — the central algorithmic primitive

A **weight order** on a Weyl algebra assigns integer weights `w(x_i) = a_i`, `w(∂_i) = b_i` and totally orders monomials by weighted-total-degree (lexicographic in case of ties). The most-used weight orders:

| Weight | Used for |
|---|---|
| `(0, 1)` — i.e. `a_i = 0, b_i = 1` | Initial ideal at `s`: compute `b_f(s)` ideal |
| `(1, 0)` — symmetric to above | Initial at `x`: degeneration toward commutative |
| `(1, 1)` | Total-degree filtration: holonomicity tests |
| Arbitrary `(a, b)` | Drestriction, Dlocalize, Dintegration algorithms |

`gbw(I, w)` and `inw(I, w)` are the workhorses — most D-module algorithms apply them at the right weight to extract the relevant filtration data.

## When this is slow

| Symptom | Try |
|---|---|
| `gbw(I, w)` slow | Weyl-algebra GBs grow fast; for low-degree input try `Strategy => NewF4` (this routes through the modern F4 engine) |
| `makeCyclic M` slow on a high-rank module | The Stafford-Smith algorithm is iterative; bound the iteration depth via the options in `WeylAlgebras/makeCyclic.m2` |
| `factorWA f` produces "no factorisation" warning | Weyl-algebra factoring is incomplete; not every reducible operator can be factored algorithmically |
| `isHolonomic M` slow | Routes through `Ddim` which routes through GB; same speed considerations as commutative GB |
