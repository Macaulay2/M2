# `IntegralClosure.m2` — integral closure & normalisation

The `IntegralClosure` package implements `integralClosure` of a
ring or an ideal, `conductor`, `icMap` (the map from the ring into
its integral closure), `icFractions` (the new generators as
fractions), the small-characteristic variant `icFracP`, plus
related helpers (`idealizer`, `ringFromFractions`, `makeS2` for
S2-ification). **Auto-loaded** — every M2 session has these
operations available without `needsPackage`.

This is the **largest auto-loaded package** at 3 587 lines + a
1 931-line auxiliary directory. It's also one of the slowest in
typical use — `integralClosure` of a non-trivial ring quotient
often dominates a workflow's runtime, which is why the package
exposes many `Strategy` options.

- Main file: `IntegralClosure.m2` (3 587 lines — single big file)
- Auxiliary directory: `IntegralClosure/` (6 files, 1 931 lines —
  mostly examples and a benchmark harness)
- Authors: David Eisenbud, Mike Stillman, Amelia Taylor
- Re-exports: [`MinimalPrimes`](file-MinimalPrimes.md)
- Imports: [`PrimaryDecomposition`](file-PrimaryDecomposition.md),
  [`ReesAlgebra`](ReesAlgebra.m2)
- Date: 31 Dec 2020 (version 1.10)

## Exported API

### Core operations

```m2
integralClosure R                    -- the integral closure R̄
integralClosure(B, A)                -- targeted: closure of A inside B
integralClosure(I)                   -- integral closure of an ideal
icMap R                              -- the inclusion R → R̄
icFractions R                        -- the new generators of R̄ as fractions in frac R
conductor(R)                         -- conductor ideal (R : R̄)
conductor(F)                         -- conductor of a ring map
icFracP R                            -- small-characteristic variant (faster for prime char p)
icPIdeal                             -- integral-closure ideal in char p
makeS2 R                             -- S2-ification of R (intermediate step)
idealizer(R, J)                      -- the idealizer of an ideal
ringFromFractions(F)                 -- build the ring generated by a list of fractions
testHunekeQuestion R                 -- diagnostic from Huneke
```

## High-level algorithm

The de Jong / Vasconcelos algorithm at the heart of
`integralClosure R`:

1. **Find the singular locus** `J ⊂ R` (`idealInSingLocus`).
2. **Build the idealizer** of `J` in its dual: this gives a new
   ring `R'` containing `R`. If `R' = R`, stop — `R` is normal.
3. **Otherwise iterate**: replace `R` by `R'` and go to step 1.
4. **Stop** when the ring stops growing. The result is the
   integral closure.

The package implements this for graded and affine rings, with
specialisations:

| Strategy | What changes |
|---|---|
| `Radical` | Use full radical computation at each step |
| `RadicalCodim1` | Cheaper — only radical in codimension 1 |
| `AllCodimensions` | Walk through all codimensions; expensive but thorough |
| `SimplifyFractions` | Aggressively simplify the new-generator fractions |
| `StartWithOneMinor` | Bootstrap with a single minor of the Jacobian, not the full minor ideal |
| `Vasconcelos` | Use the Vasconcelos variant of the idealizer step |

Pass any combination as `Strategy => {symbol₁, symbol₂}` — the
package combines them. Default: `{}` (let the heuristic pick).

## Why this depends on `MinimalPrimes` and friends

The header comment captures it:

> `PackageExports => { "MinimalPrimes" }  -- really helps speed
> up most computations here. Use minprimes.`

`integralClosure` calls `minprimes` (from
[`MinimalPrimes`](file-MinimalPrimes.md)) on intermediate ideals
to **decide where the ring is already normal** and **localise the
work**. This is why `MinimalPrimes` is re-exported — using a
different `minprimes` implementation would break the dependency.

It also imports:

- `PrimaryDecomposition` — only for the `rad` helper used in one
  obscure path
- `ReesAlgebra` — for `integralClosure(Ideal, ...)`, which builds
  on the Rees algebra of the ideal

## `integralClosure(Ideal, ...)` — version 2 disabled

Lines 822 onwards (`Integral closure of ideal`) contain
**`integralClosure(Ideal, RingElement, ZZ)`** — a second-generation
implementation that builds the Rees algebra, computes its
integral closure, then descends. The header comment says:

> "version 2. Not working yet, Dec 2020, perhaps use something
>  like this in M2 1.18?"

The block is wrapped in `-* … *-` (M2 multi-line comment syntax)
so it doesn't load. The fallback implementation that *does* load
delegates to the older logic via `ReesAlgebra`. Anyone working on
ideal integral closure today should check whether v2 has been
unblocked in subsequent releases.

## `icFracP` — small characteristic

For rings over a finite field `ZZ/p`, the package exports a faster
variant `icFracP` based on the Frobenius. It uses repeated
Frobenius pullbacks to detect new elements of the integral closure
without going through the full singular-locus iteration. Use it
when:

- The base field is `ZZ/p` with small `p`.
- The ring is reduced.
- You suspect the singular locus is large (where the generic
  algorithm slows down most).

## When this is slow

`integralClosure` is genuinely expensive. Knobs to try:

| Symptom | Try |
|---|---|
| Hangs at the first idealizer step | `Strategy => {RadicalCodim1}` — much faster than full Radical |
| Many `minprimes` calls in `Verbosity > 0` output | Likely working — `MinimalPrimes` is doing real work; consider `Strategy => {Vasconcelos}` to avoid them |
| Finite-characteristic input | Switch to `icFracP` |
| Want the conductor only | Use `conductor R` directly — usually faster than `integralClosure R` followed by `conductor icMap R` if you only need the conductor |
| Want a partial result for debugging | `Verbosity => 3` prints each iteration's progress and intermediate ring sizes |

The `runexamples.m2` file in the aux directory is the gold-standard
way to compare strategy performance — it runs each example under
each strategy and reports timings.
