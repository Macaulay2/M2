# `scclib.c` — `scc1` runtime support library

`scclib.c` is the **C-side runtime support library** for code
generated by [`scc1`](../c/README.md). When a `.d` file is
translated to C, the resulting code calls into helpers declared
here for garbage collection, memory allocation, exception handling,
and other primitives the `.d` language assumes.

Part of the [`d/` interpreter layer](README.md).

[← back to d/ overview](README.md) · [← top-level engine TOC](../../../README.md)

## What it provides

Generated `.d`-to-C code needs more than what stdlib offers:

- **GC-managed allocation** — `getmem`, `getmem_atomic`,
  `getmem_clear` from
  [`../e/interface/file-m2-mem-interface.md`](../e/interface/file-m2-mem-interface.md).
- **Sum-type runtime helpers** — `.d`'s `when ... is ...` pattern
  matching expands to C code that branches on tag fields; `scclib.c`
  provides the tag-test helpers.
- **String / array runtime** — variable-length structures the `.d`
  language compiles to.
- **Error / longjmp targets** — `err_abort`, `err_fatal`, exception
  unwinding.
- **Atomic operations** — the `atomic` field protocol from
  `atomic.d` / `atomic2.d`.

## Comparison with `M2lib.c`

`scclib.c` and [`M2lib.c`](file-M2lib.md) are both C support files
for the interpreter, but they differ in scope:

| File | Role |
|---|---|
| `M2lib.c` | Top-level startup, readline, signal handling |
| `scclib.c` | Runtime support called by `scc1`-translated code |

`scclib.c` is called for every generated C function; `M2lib.c` is
called once at startup.

## Why a separate file

The `scc1` translator can be developed and used independently of
M2 — anything written in `.d` needs a runtime, and `scclib.c` *is*
that runtime. Splitting it from M2-specific concerns keeps the
boundary clean.

## Used by

- Every `.d`-to-C translation unit at runtime.
- `scc1`'s own self-hosting (if applicable).
