# `M2lib.c` — interpreter `main()` / startup glue

`M2lib.c` is the **C glue** that ties the M2 interpreter together
into a runnable program: it sets up signal handlers, initialises
the garbage collector, starts the readline-based prompt, and
hands control to the interpreter's main loop.

Part of the [`d/` interpreter layer](README.md).

[← back to d/ overview](README.md) · [← top-level engine TOC](../../../README.md)

## Header preamble

```c
/*		Copyright 1994 by Daniel R. Grayson		*/

#include "expr-exports.h"

#include "M2mem.h"
#include "types.h"
#include <interface/m2-mem.h>
#include "supervisorinterface.h"

#include <readline/readline.h>
#include <readline/history.h>

extern struct JumpCell abort_jmp;
extern struct JumpCell interrupt_jmp;
```

Three pieces of machinery surface in the includes:

- **`expr-exports.h`** — generated by `scc1` from the `.d` files;
  exposes everything the C code needs to talk to the interpreter.
- **readline** — GNU readline for line editing at the prompt.
- **`JumpCell`** — `setjmp`/`longjmp` cells for handling `abort`
  and Ctrl+C.

## What it does

`M2lib.c` is essentially the **`main()` shim**:

1. Parse command-line arguments.
2. Initialise the bdwgc GC.
3. Set up the supervisor for threading.
4. Install signal handlers (`SIGINT`, `SIGTERM`, `SIGSEGV` for
   crash reports).
5. Initialise `setjmp` targets for the abort / interrupt longjmp.
6. Configure readline.
7. Call the interpreter's startup function (declared in `interp.dd`).

After step 7, control flows into M2-level code (the `.m2` files in
[`../m2/`](../m2/README.md)) and the interpreter loop runs until
exit.

## Hand-off to `.d` code

Once `M2lib.c` has done its setup, the action moves entirely into
generated C from `.d` files. The hand-off point is a call to the
M2 startup function (typically `interp_setupargv` or similar).
After that, every M2-level expression evaluation flows through the
`.d`-generated machinery.

## Why C, not `.d`

Initialisation code touches `errno`, signal handlers, environment
variables — things `.d` doesn't have direct primitives for. Plus
`main()` itself must be plain C linkage. So `M2lib.c` is C; the
heavy lifting lives in `.d`.

## Used by

The whole interpreter — this is the entry point.
